# 环境与启动

仓库的Skill入口是`skills/xiaoteng-storyboard-style-4-0/SKILL.md`。安装目录与学员工程分开，已有其他风格Skill可共存。

## 识别本机与复用依赖

先识别操作系统（macOS、Windows或Linux）、CPU架构与现有Node.js。需要Node.js 22以上，建议24；Windows使用x64 Node.js。固定依赖版本由工程package.json与package-lock.json决定，Remotion为4.0.484；不直接混用其他版本的依赖目录。

首次使用，在用户指定位置或当前项目outputs内创建独立学员工程：

```bash
node "<Skill目录>/scripts/init-project.mjs" "<学员工程绝对路径>"
```

已有本学员工程继续在原目录工作。`--resume`只补充缺失文件，不覆盖已有内容；不把空白示例覆盖到学员已编辑的项目。

在工程目录执行一次：

```bash
npm run setup
```

准备入口先输出本机系统、架构、Node版本和内存信息，再按以下规则处理：

- 现有工程依赖版本完整匹配时直接复用，不重复安装。
- 需要准备依赖时，若存在`~/.codex/shared-node-dependencies/ensure.mjs`，先调用该工具；否则按锁文件、npm、Node主版本、操作系统和架构建立或复用全局运行组。Windows用junction链接依赖，其他系统用目录链接；不在已链接的共享node_modules内直接改包。
- FFmpeg/FFprobe优先复用`FFMPEG_PATH`/`FFPROBE_PATH`明确指定的工具或本机可用工具；没有时使用当前Remotion依赖自带的对应系统二进制，无需另行下载独立安装包。明确指定的路径无效时提示修复。
- 字体先校验本地摘要，缺失或不匹配时才从官方地址下载；准备系列公共素材。来源和摘要在`scripts/font-sources.json`。
- 浏览器优先复用当前运行组中与固定Remotion版本匹配的Chrome Headless Shell缓存；缺失时首次下载。可用`REMOTION_BROWSER_EXECUTABLE`指定本机已验证的兼容浏览器。已有共享运行组的工程共用其浏览器缓存。
- 本模板不需要Python或NumPy，不为视频制作重复建立Python环境。

准备中断后可重跑`setup`，已有可用部分会复用。同一依赖正在安装时入口提示稍后重试；不并发修改同一运行组。

## 日常制作

```bash
npm run check
npm run render:demo
```

正式入口保持为：

```bash
node "outputs/分镜素材制作/4.0模板/渲染.cjs" render "分镜规划/{期名}/镜头契约.json"
```

默认检查契约、字体、素材、排版和输出规格（帧数、分辨率、帧率及与录音设置对应的音轨）。保留现有1920×1080、30fps、CRF16、PNG及材质绘制等待，完成后从实际成片生成预览合集图，查看一遍排版。按CPU、总内存及空闲内存自动选1或2并发，低内存默认1；可追加`--concurrency=1`。渲染结束记录并发、准备和段落耗时。

已经准备好的工程可以直接继续制作；`doctor`用于环境排错，不要求每次完整初始化。视频有多个合成段落时，命令末尾可传指定合成ID，仅重渲染这些段落，其他段落校验已有SHA后复用；同一合成内部不提供断点续渲。

## 音频与排版检查

输入文案、时间码字幕和原始音频，在本期契约登记`audioFile`（相对`outputs/分镜素材制作`的路径或本机绝对路径）。原录音需覆盖各段`sourceStartMs/sourceEndMs`，渲染入口按这些源时间裁取声音，以原速度合入成片；画面段尾保持补静音。未提供录音的仓库演示是纯画面，不生成虚构声音。

设计时确保文字在框内、独立文本框不相交、文字不覆盖其他框体、底部字幕区留白。轻量检查发现排版问题会停止渲染。输出完成后自动生成`{视频名}-预览合集.png`，包含各镜头及轮播状态的时间点。Codex打开合集图检查一遍后再交付和进入学员审片；自动记录不代替人工看图。

## 审片与平台范围

渲染通过后自动启动或复用本学员工程的审片台，只链接原视频，使用源路径与SHA刷新，不复制或备份视频。优先4328端口；被其他工程占用时选择独立空闲端口并输出实际地址。手动恢复用`npm run station`，无图形环境可设置`NO_OPEN=1`。不自动播放，不代用户验收。

macOS和Windows共用源码，由系统识别选择原生依赖、浏览器和链接类型。中文及空格路径使用完整引号。Windows ARM环境需使用当前固定版本支持的x64 Node.js运行环境；不能据此宣称原生ARM64已验证。运行`node scripts/check-portability.cjs`可检查Windows/POSIX路径编码；路径与逻辑检查不等于另一系统已完整渲染。Windows仍需实际设备验证。
