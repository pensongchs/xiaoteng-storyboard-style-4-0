# 小滕分镜风格4.0版

这是可独立运行的学员版本，画面使用中性内容与说明图形。使用本包的模板和两套组件库；不读取或覆盖其他人的自用模板、目录、身份素材或审片记录。

## 开始与工程入口

先读当前任务目录的AGENTS.md。先识别学员电脑的操作系统、CPU架构和现有Node.js。首次使用按[环境与启动](references/环境与启动.md)创建独立工程，执行`npm run setup`匹配本机依赖并接入随包字体；优先复用版本一致的工程依赖、共享运行组、本机工具和浏览器缓存，只准备缺失部分。续接已有学员工程，保留当前内容，不重复安装完整环境。所有运行路径从本Skill或学员工程位置解析，不使用作者电脑路径。

读取学员工程的`outputs/分镜素材制作/4.0模板/模板总指令.md`，按[目录与组件调用](references/目录与组件调用.md)定位本期、共享库和自制组件。详细布局和固定参数以工程内同一份模板及实际代码为准。

## 制作要点

- 先理解文案，再按提问、比较、风险、数据、步骤或品质关系安排画面。保留4.0字面、层级、材质、统一内容层和底部字幕区；每期重新布局，不照抄示例的镜头顺序或具体台词。
- 每期实际调用至少5种不同共享库效果，其中至少一种为图片轮播。其他内容通常以约80%的自制组件、20%的内容MG搭配；用户指定比例时以当次要求为准，按内容单元记录，不能冒称播放时长比例。
- 图片轮播至少两张与文案相关的不同图片，逐张配标签和说明，图片区和文字区分开规划；检查文字与图片、卡片之间的遮挡和间距。
- 每个不同画面之间都有轻量转场，依据[转场与轮播](references/转场与轮播.md)配置。保留真实时间线和整片时长，不靠重叠扣减源时间或提前显示下一镜关键词。
- 新文案显式传入关键词、语义色、图片和时码。使用本包的归档实现及公共素材；原始共享库里未适配或缺少主结构的条目，需先完成本期适配并验证，不能仅导入或列编号。
- 以真实毫秒和词元驱动画面，30fps统一使用ceil(ms×30/1000)。无词元时使用句级动作，不均分句子伪造精确触发。遇到明显字幕错字只修文字，不擅自改时码。

## 输入、时间线与声音

学员提供文案、SRT或词元时间轴，以及原始音频。按文案内容重新设计画面，不照搬示例的镜头顺序；画面进入、停留和转场以真实字幕与音频的同一播放时钟为准。只有句级字幕时使用句级动作，可把整句保留为一个原时间跨度的token，不均分或猜测逐字时间。字幕与音频明显不对应时先核对来源，不能靠拉伸音频凑时间。

在契约中登记`audioFile`，使用原始音频；输出视频保留声音，供学员在审片台检查音画同步。多段输出按各段`sourceStartMs/sourceEndMs`裁取同一原音频，段尾画面保持只补静音，不改变语速。用户明确要求纯画面时可不登记音频；仓库演示未附录音，保持纯画面示例。

## 渲染、合集图与审片

将本期契约、词元、轮播、转场和来源记录放在本期期名目录，运行模板的`check`与正式`render`入口。设计时让文字完整留在各自框内，独立文本框之间留出间距；文字不可越框、遮挡别的文本框或侵入字幕区。运行时保留轻量排版检查，发现重叠及时停止并提示位置。保留字体、素材、时间线及输出规格检查，使用正常逐帧采集；无需Python或NumPy。按本机CPU和内存选择1或2并发，可用`--concurrency=1`降低负载。

渲染完成后，自动从实际成片抽取各镜头与轮播状态，生成带时间点的`{视频名}-预览合集.png`。打开合集图检查一遍，重点看文本框重叠、文字越框或遮挡、字号、字幕留白与图片标签；有问题修改原工程再渲染。只有实际看过合集图后，才把检查记录的`previewReview`改为true；这与学员最终验收分别记录。

正式渲染通过后，自动启动或复用本工程审片台，载入带原始音频的最新MP4。使用实际源路径与SHA刷新缓存；审片台只链接原视频，不复制或备份视频。会话仅保存当前源路径等必要信息；不自动播放或代学员验收。按批注时间与选区修改同一期并重新载入。交付视频、预览合集图和简短说明。
