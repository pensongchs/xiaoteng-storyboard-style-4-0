# 自媒体本地动效库

这个目录只负责保存和管理用户提供的动效代码与对应截图，供整个 `当前项目` 项目调用。

## 调用边界

1. 分镜素材、口播插入画面、动态图文包装和独立分镜视频自动调用本地动效库；完整选材、数量、类型、适配、时间驱动和交付规则统一读取 `../分镜素材制作/4.0模板/模板总指令.md`。分镜制作无需再读本文件的通用调用说明；候选项的截图、单项README和源码按需要核对。
2. 片头、开场、封面、真人出镜整片和其他类型任务，仅在用户明确要求调用素材库或点名动效时使用，按对应视频模板及下方共用规则适配。
3. 动效站点开发、整批同步与发布只在用户明确要求对应站点任务时进行，与视频的本地选材独立。

## 固定整理方式

每项动效建立一个独立文件夹，文件夹名称为：

```text
{三位编号}_{中文名称}/
```

同一项动效的所有内容都放在这个文件夹中：

```text
001_左右摇摆数字卡/
├── 001_左右摇摆数字卡_截图.png
├── 001_左右摇摆数字卡_代码.html   用户提供代码后保存，扩展名按原代码类型确定
└── README.md                       来源、用途、代码状态和备注
```

## 保存规则

1. 用户给出代码后原样保存，不主动改写、适配、注册或渲染。
2. 对应截图与代码必须放在同一个动效文件夹，不再拆分“参考素材”和“待整理源码”目录。
3. 代码可能包含多个文件时，仍放在同一动效文件夹内，并保留原始文件名或使用清楚的功能名。
4. 有来源网址、作者、许可证或使用限制时，写入该动效文件夹的 `README.md`；无法确认的信息标为“待确认”，不得猜测。
5. 新素材依次使用 `002`、`003` 等编号，并同步更新根目录的 `动效登记表.md`。
6. 除非用户另外要求，不为归档素材生成 Remotion 组件、预览视频、静帧或其他派生文件。

## 收集与统一同步总流程

1. 用户连续提供最新动效截图和代码时，每收到一项只完成本地归档：建立编号文件夹、保存原始代码和截图、补充单项 `README.md`、更新 `动效登记表.md`。
2. 单项收集阶段不运行站点同步脚本，不构建、不发布，也不把本地新增素材临时塞入正式管理台。
3. 只有用户明确表示“这一波收集完毕”“统一归档”“统一同步网站”或同等含义时，才开始整批同步。
4. 整批同步前先核对本批全部编号、文件、截图、登记表、来源说明和缺失依赖；有代码不完整时如实标注，不自行补写为完整组件。
5. 整批同步时一次性运行管理台同步、构建和发布，复用 `outputs/动效库管理台/site/.openai/hosting.json` 中的固定项目 ID，不创建新站点、不更换正式地址。
6. 正式管理台只使用固定 Sites 地址，不把 `localhost`、`127.0.0.1`、临时预览地址或会过期的链接作为正式入口；保留当前账号私有访问，不主动改成公开站点。
7. 发布完成必须确认部署成功、站点素材数量与本地登记表一致、新增截图和源码可读取，并把固定正式地址交付给用户。若站点无法由 Codex 直接读取，整批同步任务中同时修复访问链路和站点配置，不把失效状态留到下次。

## 视频调用时的原版适配规则

1. 原始截图和源码是动画与材质基准。保留主要动画、运动路径、缓动、状态切换、关键形状和材质层次；内部图片、中文文字和配色按本期文案及对应模板匹配。
2. 插入效果服从对应模板的总布局、主字体和视频主体。原尺寸适配时保留；过大或越过安全区时整体等比例缩小，不拉伸内部比例，仍不合适就换选。
3. 实体、图片和字形后方不能有长方形阴影或硬边暗块。卡片可保留自身底面和沿真实轮廓自然衰减的投影；原版含方块影时在本期适配层处理或换选。
4. 只在本期适配层修改内容、中文排版和自动触发过程，原始归档文件保持不变；替换后核对完整动作、光影层次、可读停留和对应视频安全区。

## 交互动效用于视频时的通用规则

1. 用户提供的代码如果依赖点击、悬停、聚焦、按下、拖动、滚动、输入或其他网页交互，归档时仍保留原始代码，不提前改写。
2. 动效正式用于视频时，把交互状态转换为按视频时间轴自动触发，不等待观众操作。
3. 自动触发顺序必须保留原交互的语义，例如“默认状态 → 触发反馈 → 状态变化 → 保持或退出”，不能只播放无意义的循环。
4. 具体触发帧、持续时间和退出方式按当期文案、字幕时间码、镜头时长与画面节奏确定。
5. 分镜类任务的自动匹配范围和其他类型任务的调用边界，以《项目总指令》为准。
6. 实现前以同文件夹的效果截图和源码核对动画、材质光影与触发前后状态，同时确定按文案匹配的配色、图片和文字；实现后用原动作与视频关键帧对照，检查动画完整性、本期内容和阅读效果。原始文件保持不变。

## 视频调用时的中文文字规则

1. 归档阶段保留素材原有的数字、英文和演示文字，不改写原始代码。
2. 某项动效正式用于视频时，动效里的可见文字必须根据当期文案重新填写，不能沿用示例中的 `Generate`、`Generating`、数字 `6` 或其他无关占位内容。
3. 用户文案默认以中文为主。调用时必须重新检查中文字体、字形完整性、字号、字重、字距、行距、对齐、换行和承载区域，不能直接沿用为英文字母设计的宽度与间距。
4. 中文字体优先使用项目现有本地字体和《项目总指令》的字体规则；必须确认所用字体覆盖当期全部汉字、数字和标点，不得出现缺字、替代字形或字体回退造成的风格断裂。
5. 逐字、逐字符或字母延迟动效改为按照中文字符和语义节奏拆分；标点是否参与动画根据阅读节奏决定，不能机械套用英文 `nth-child` 间隔。
6. 文案较长时，优先缩短画面文字、合理换行、扩大承载区域或拆成多个状态；不得为了塞入原组件而把中文缩得过小、挤压字距或让文字超出边界。
7. 最终排版必须遵守当前视频类型的文字安全区、字幕安全区和平台按钮安全区，并在正式制作时检查关键帧中的文字完整性。
