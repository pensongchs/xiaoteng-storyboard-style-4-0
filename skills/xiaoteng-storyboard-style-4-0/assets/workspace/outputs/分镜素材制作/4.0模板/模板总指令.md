# 分镜风格4.0学员模板

这是本学员工程唯一模板入口。固定设置读取参数.ts和组件源码，本期内容保存到本期目录。模板不绑定账号、人物形象或某一期固定镜头脚本。

## 风格与画布

1920×1080、30fps、H.264、CRF16、PNG采集、yuv420p，提供录音时保留原始声音供审片。设计坐标1280×720，背景全屏；内容层left=76.8、top=-22、scale=.88，外层统一放大1.5。底部输出y900起留给后期字幕。组件不重复套全局变换。

保持石墨深底、暖白正文、沙金或语义色强调、柔和内光、细亮边和克制阴影。实景使用自然白平衡；库项保留自己的主要色彩和关键动作，作为局部强调。不要整体叠加蓝色滤镜。

学员版统一使用可自动取得的阿里健康体2.0：45R用于正文，85B用于标题、标签与强调数字。BFBody、BFTitle及Arial为工程注册别名，准确文件与摘要在资源锁及字体下载清单中，不读取系统临时回退字面。字体等待成功后才绘制。

章节标题使用Heading40，默认56设计像素，范围38～64；普通正文32，信息卡说明24，不低于22；标签根据内容一般25～56。宽度先测量实际字面，长词按语义换行或增高，最多三行，不无限缩字、不拉伸字形。文本与框体左右至少23、上下至少14设计像素，线框间距至少6。

## 根据文案布局

先判断当前句在提问、比较、说明风险、展示数据、列条件还是解释品质，再确定实景、卡片、图解和运动。标题给判断，卡片放精简关键词或条件，不逐句铺满口播。短标签随字宽收缩；比较、重点和图文关系可使用中大卡片，文字、图形与留白要协调。

提问或二选一以整组居中；正反变化用左右对照或文字配方向图解；风险强调主风险、次要条件为辅；数据用共同尺度、语义色、标签和数字关联；步骤依次进入；品质用实景配说明。一个时刻保持一个主动作，图片与模型可以轻运动，正文驻留时保持稳定。

所有内容按本期文案重新挑选和布局，不固定复刻示例顺序。仅示例中的素材确与新内容一致时才复用；新期图片、数据、说明与结论有明确来源。人物组件不作为本学员版内容。

## 双库与轮播

共享库位于outputs/动效素材库，保留原始代码、截图和署名；自制库在本模板自制动效组件，2个系列18项。先读目录再读相关条目。每期实际调用至少5种不同共享库效果，至少一种是图片轮播；自制与原创MG单独统计，通常约80%/20%，以用户当次要求为准。

轮播至少两张不同、相关图片，每张有标签、说明和真实触发时间。图片区、说明区、卡片区分开规划，对齐、留间距，避免覆盖图中主体。轮播用StudentExtras40的CarouselCaption40可直接接入；其他图库形态先完成帧驱动适配。共享条目中的鼠标交互改为按真实词元自动播放，不能只导入或静态摆放凑数。

自制Z001为Capsule、Z002为PearlCard、Z003为GlassPanel；Z004～Z018为对应关键词框。S002传入本期content、颜色、插图和时码；未指定插图时采用无插图比例。两行、清单、并列内容分别使用lines或columns。组件源文件和系列公共实现保持稳定，本期适配保存在本期src。

## 时间线与转场

F(ms)=ceil(ms×30/1000)，时长帧数为F(end)-F(start)。忽略输入JSON里的旧fps及派生帧字段；保留真实毫秒、停顿和词元顺序。只有句级时码时使用句级动作，不均分伪造词元。

每个不同画面边界都配置轻量转场，记录transitions的atMs、kind、frames。默认12帧，可用6～20帧wipe或iris；完整画布调用SceneTransitions40。转场先遮住旧镜，再在原边界露出新镜，不减总帧数、不提前下一镜关键词。进入、阅读、退出和转场都在真实时长内完成。

默认组件按原有移动、弹簧或库动作进入，不反复重启驻留文字。用户给定成片时长优先；若使用30帧段尾保持，入口用HoldLastFrame40并在输出时间线上明确计入，不能顺带延长用户指定总时长。

## 本期文件与契约

每期保持一个稳定期名：src保存内容和独立入口，public/{期名}素材保存正式素材，分镜规划/{期名}保存镜头契约、词元、动效调用和内部检查，renders/{期名}保存成片。共享字体和系列公共资源不在每期重复建运行环境。

契约含title、styleId、entryPoint、assetRoot、cuesFile、outputDir、internalDir、motionLibraryFile、videos、scenes、carousel、transitions。styleId为storyboard-glass-4.0-student。videos保留sourceStartMs/sourceEndMs/holdFrames；scenes完整覆盖输出段落并登记screenText、assets、beats。实际结构参考分镜规划/学员示例/镜头契约.json；示例台词和图片不是新期固定要求。

## 输入、声音与检查

学员提供文案、时间码字幕和原始音频。按文案语义设计布局，真实时间线决定进入、驻留与转场。契约登记audioFile，声音按各段sourceStartMs/sourceEndMs从原录音裁取，保持原速度；画面与声音使用同一源时钟，段尾保持仅补静音。纯画面须由用户明确要求；仓库演示未附录音。

首次识别系统、架构与现有工具，用npm run setup复用可用依赖、字体及浏览器缓存，只准备缺失部分。日常运行check与render。设计时确保文字完整留在各自框内，独立文本框间留有间距；文字不越框、不覆盖其他框体，不侵入后期字幕区。保留字体、素材绘制等待、轻量排版和输出规格检查，出现重叠时及时停止并提示。

正常逐帧PNG采集，按本机CPU和内存选1或2并发，可用--concurrency=1降低负载。成片输出后自动抽取各镜头与轮播状态，生成带时间点的预览合集图；打开看一遍文本框、文字、图片标签及字幕留白。实际看过后记录previewReview，学员最终验收另记。无需Python或NumPy。

正式入口：node outputs/分镜素材制作/4.0模板/渲染.cjs check 分镜规划/{期名}/镜头契约.json；将check换成render即渲染、生成合集图并载入本地审片台。

审片台直接链接本工程最新成片。自动启动或复用同工程服务，验证路径、文件大小与SHA；端口被其他工程占用时分配空闲端口并输出地址。不自动播放，不代学员验收；按批注返修继续同一期。视频只保留原路径，不复制或备份，返修后刷新原文件链接。
